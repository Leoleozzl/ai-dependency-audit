## 🚀 快速开始

### 1. 扫描项目中的AI依赖

```bash
node tools/scanner.js <你的项目路径>
```

**示例**：
```bash
node tools/scanner.js ./my-ai-project
```

**输出**：`scan-result.json`（包含所有AI调用点、配置位置、Prompt模板）

### 2. 生成可视化报告

```bash
node tools/report-generator.js ./scan-result.json
```

**输出**：`audit-report.html`（可在浏览器中打开）

### 3. 运行模型替代性测试（可选）

**步骤1：创建配置文件**
```bash
node tools/substitution-test.js ./test-config.json
# 会生成示例配置，编辑后填入真实API Key
```

**步骤2：运行测试**
```bash
node tools/substitution-test.js ./test-config.json
```

**输出**：`substitution-test-result.json`（包含分类一致率、JSON正确率、响应延迟等指标）

## 📖 方法论核心

### 四步审计法

```
① 依赖发现 → ② 关键性评估 → ③ 可替代性验证 → ④ 演练报告
```

#### ① 依赖发现（Dependency Mapping）

找出所有AI调用点：
- **模型服务**：API端点、模型名称
- **账号权限**：API Key、配置存储
- **业务规则**：Prompt模板、分类逻辑
- **人的经验**：谁知道怎么调教模型

**工具**：`scanner.js` 自动扫描代码

#### ② 关键性评估（Criticality Assessment）

评估"AI挂了业务能不能活"：
- **5分（极高）**：核心流程完全停摆
- **4分（高）**：重要功能不可用
- **3分（中）**：辅助功能受影响
- **2分（低）**：边缘功能异常
- **1分（极低）**：几乎无影响

#### ③ 可替代性验证（Substitutability Check）

验证"能否切换到其他模型"：
- **模型切换测试**：用备选模型跑10条真实数据
- **评估指标**：
  - 分类一致率 ≥70%
  - JSON格式正确率 ≥90%
  - 平均响应延迟 <5秒

**工具**：`substitution-test.js` 自动化测试

#### ④ 演练报告（Exit Drill Report）

模拟"AI中断5小时"场景：
- 列出受影响功能
- 计算恢复时间
- 识别残留问题

## 🔧 工具详解

### scanner.js - 代码扫描器

**功能**：
- 递归扫描项目文件（支持 .ts / .js / .py / .java）
- 检测AI API调用（`/chat/completions` / `/audio/transcriptions` 等）
- 提取配置项（`api_key` / `base_url` / `model_name` 等）
- 识别Prompt模板（`SYSTEM_PROMPT` / `USER_PROMPT` 等）

**特点**：
- 正则匹配，不依赖AI
- 自动排除 `node_modules` / `dist` 等目录
- 支持多行Prompt提取

### report-generator.js - 报告生成器

**功能**：
- 读取扫描结果JSON
- 计算关键性分数
- 生成HTML可视化报告
- 按文件分组展示

**报告内容**：
- 统计卡片（文件数/调用点/配置点/Prompt点）
- AI服务依赖点（含代码位置和代码片段）
- 配置存储位置
- 业务规则（Prompt模板，可展开查看完整内容）

### substitution-test.js - 模型替代性测试

**功能**：
- 准备测试样本（10条真实/模拟数据）
- 用基准模型跑一遍
- 用备选模型跑一遍
- 对比结果：分类一致率、JSON正确率、响应延迟
- 判断可替代性（≥70%一致 + ≥90%格式正确 = 可替代）

**注意**：
- 当前版本使用**模拟数据**
- 真实场景需要连接数据库读取记录
- 需要提供真实的API Key

## 🎓 真实案例学习

### 案例：智能个人记录本

**项目背景**：
- 功能：多模态输入（文本/语音/图片）→ AI自动分类 → 任务提醒
- 技术栈：React + NestJS + PostgreSQL + OpenAI兼容API

**审计发现**：
1. **Ⅱ象限（高危依赖）**：文本识别服务
   - 关键性：5/5
   - 可替代性：中（有2个备选但需手动切换）
   - 风险：模型中断 → 所有新记录无法分类

2. **Ⅳ象限（隐患依赖）**：配置存储
   - 关键性：3/5
   - 可替代性：低（无导出/备份机制）
   - 风险：用户删号 → 配置全丢

**修复建议**：
- **P0**：接入LiteLLM故障转移网关（<1秒自动切换）
- **P1**：增加配置导出/备份功能
- **P2**：Prompt外部化（便于版本管理）

完整案例见：[案例-智能个人记录本审计报告.md](./案例-智能个人记录本审计报告.md)

## 🛡️ 安全性说明

### API Key 处理

**扫描器（scanner.js）**：
- ✅ 只检测配置项的**存在位置**
- ✅ 不提取、不存储、不传输API Key内容
- ✅ 代码片段最多显示前100字符

**报告（audit-report.html）**：
- ✅ 不包含任何敏感信息
- ✅ 只显示文件路径和行号
- ✅ 可安全分享
